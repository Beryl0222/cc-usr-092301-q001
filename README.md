# 商场趣味赛安全联动

区域运营中心统一管理门店趣味赛事的运行内核：空间版本、玩法与风险级别、
报名资格、分时入场、候补、现场分组、裁判记录、奖品、商户协作、客流观测、
应急处置与素材授权。

本仓库保存业务参与方确认的**事件信封合同、事件词表、事件溯源领域模型与
最小校验/测试代码**，供后续服务沿用共同标识和时间语义。纯标准库实现。

## 运行检查

```bash
python -m unittest discover -s tests -v
```

## 模型结构

```
src/
  contract.py     信封字段与带时区时间语义
  store.py        事件存储：流内版本连续 + command_id 幂等
  domain.py       聚合：全部业务规则在命令侧判定，事件即事实
  projections.py  读模型：占用、顾客看板、授权目录、体验指标（纯重放）
  app.py          应用服务：跨聚合规则（分区容量、分区暂停、发布判定）
contracts/
  event.schema.json  信封合同 + 事件类型词表（kind 枚举）
```

一切状态都是事件的投影：拿同一份事件日志可以完整重建门店视角与顾客看板
（见 `test_state_rebuilds_from_event_log`、`test_events_replay_rebuilds_board`）。

## 关键规则如何落地

**名额不能被消息制造。** 报名、签到、入场都带 `command_id`，存储层与聚合层
双重幂等：重复扫码、断网补签重放返回原事实，不新增事件。候补只在
*签到截止前*有人退出时按 FIFO 递补；截止后的取消、缺席清理
（`NO_SHOW_CANCELLED`）不产生新名额，顾客看板上 `accepting=false` 且
`open_slots=0`，而不是显示一个可被误订的空位。已出票队伍退出会同步回收票，
占用计数随之真实下降。

**参赛者与围观者分开计算。** 空间版本的每个分区有独立的
`participant_cap` / `spectator_cap`；入场前按“当前在票 + 本队人数”做分区级
硬校验，围观超容量时引导至溢出观赛区，而不是占用消防通道。

**只暂停受影响区域。** 消防通道被占或邻铺拥堵时，`ZONE_PAUSED` 只落在具体
分区，并要求随附面向已到场者的可执行安排（原地等待 / 转场 / 溢出区 /
优先返场）。同店其他分区的场次状态不变；暂停不取消已出票队伍的资格。

**资格与消费脱钩。** 报名材料只接受 `age / guardian_present /
safety_notice_signed`，任何消费金额、会员等级、积分字段在报名时直接被拒；
奖品只能按裁判成绩名次颁发（`PRIZE_AWARDED.basis=RESULT_RANK`）；体验度量
只有评分与停留时长。

**开始前检查。** 场次冻结（`SESSION_FROZEN`）要求场地确认、与风险级别匹配的
安全人员与裁判人数、应急预案；低龄活动还必须设未成年人监护核验岗。
未冻结的场次不能开放报名。

**拍摄授权与未成年人保护。** 授权按人按范围（PHOTO/VIDEO/LIVE）记录，
未成年人授权必须由监护人作出。发布判定以**发布时刻**为准：拍摄之后撤回，
发布即被拦截（`MINOR_CONSENT_WITHDRAWN`），撤回后重新授予方可恢复；
下架有请求/确认闭环。

**安全事件敏感材料。** 受伤、未成年人走失等事件的材料默认敏感，只有被指派的
实际处置人员可访问，且每次访问写 `INCIDENT_MEDIA_ACCESSED` 留痕；
走失闭环要求监护核验方式（接送码+照片比对等）。事件、响应、暂停、访问记录
共同构成可还原现场的审计时间线。

## 事件流标识约定

| subject 前缀 | 含义 |
| --- | --- |
| `space:<store>` | 门店空间版本（分区/容量/消防标记） |
| `catalog` | 活动玩法目录与风险级别 |
| `session:<store>:<id>` | 一场活动的完整生命周期 |
| `zoneops:<store>:<zone>` | 分区暂停/恢复与客流观测 |
| `incident:<id>` | 安全事件、处置人员与材料访问 |
| `consent:<person>` | 个人（含未成年人）拍摄授权 |
| `media:<asset>` | 素材登记、拦截与下架 |
| `board:<store>` | 商户协作任务 |
| `experience:<store>:<session>` | 体验与停留样本 |
